# 前端重构指导与规则约束

> 面向继续优化、重构或用 Open Design 重新生成前端的同学。
>
> 本文件只整理“必须遵守的产品语义、交互边界、视觉方向和验收规则”。它不是需求脑暴，也不是项目介绍。若本文与代码或更底层契约冲突，先停止修改，回到对应契约文件核对，不要自行改写产品语义。

## 1. 产品定位

《最后一页进步报告》是围绕《献给阿尔吉侬的花束》核心矛盾创作的 AI 协作式互动阅读体验。

它要帮助读者思考：同一个生命在不同认知阶段表达了相互冲突的意愿时，哪一个阶段的自我有权代表“真正的他”。

前端必须守住这些边界：

- 不是聊天机器人。
- 不是心理测试、人格测试、道德测试或智力下降模拟。
- 不是闯关游戏、分数系统、好感度系统或多结局剧情树。
- 不是原著续写、遗失章节复原或原文仿写。
- 不评价读者是否“正确”“善良”“共情能力强”。
- 不把 AI 输出伪装成原著事实、原著引文或可信结论。

## 2. 体验流程不可被前端改写

前端可以重构排版、动效、组件和信息层级，但不能改变阶段顺序、阶段含义或业务状态。

固定流程是：

1. 欢迎与原创声明
2. 三张查理肖像预览
3. 初次选择“最接近真正查理”的阶段
4. 三轮手稿审校
5. 精确版与朴素版生成
6. 语义复核
7. 语义花束安放
8. 重新拼合三次看见
9. 当前查理签名审阅
10. 文稿归宿
11. 只读完成封套

禁止：

- 增加第四轮。
- 把流程改成自由聊天。
- 跳过用户确认直接修改正文。
- 把“拒绝唯一答案”解释成某个阶段的胜利。
- 把完成封套做成仍可编辑的普通页面。

## 3. 当前交互语义

### 3.1 每一幕只给一个主任务

每个阶段都应该让读者一眼知道：

- 我现在在哪一章；
- 我现在要读什么；
- 我现在唯一最重要的动作是什么；
- 我是否正在等待保存、模型结果或技术检查；
- 我能否安全返回或继续。

不要把大量并列选择同时摊开。次级状态、技术说明和补充选项应使用渐进披露，但不能隐藏主任务。

### 3.2 手稿修改必须由读者确认

Agent 或模型只能生成候选。前端不能让模型结果自动进入正文。

必须保持：

- Diff 待审阅时，明确展示变更内容。
- 接受修改与拒绝保留分歧是两个不同动作。
- 正文变更后，相关 revision、朴素版、语义复核和签名审阅会失效并重建。
- 不允许用一个“智能优化”“自动润色”按钮绕过确认。

### 3.3 精确版、朴素版和语义花束必须分清

前端必须让读者看出三者不是同一个东西：

- 精确版：保留复杂限定与原始语义边界。
- 朴素版：更易读，但可能损失限定。
- 语义花束：收纳朴素化后无法完整传递的意义。

当前 UI 约束：

- `SEMANTIC_PLACEMENT` 不再给读者三选一处置菜单。
- 未安放碎片只保留一个主动作：`收入语义花束`。
- 已安放碎片只显示安静结果：`已收入语义花束`。
- 不要恢复“恢复到朴素文本 / 保存为页边批注 / 放入语义花束”的并列按钮。

### 3.4 签名不是由读者决定

签名页尤其要避免错误授权感。

读者可以做的是：

- 提交给查理审阅；
- 暂不发起审阅，继续归档；
- 返回修改手稿。

读者不能做的是：

- 直接选择“同意签名”。
- 直接选择“明确拒绝”。
- 直接选择“技术未完成”。

前端命令也不能重新暴露 `signed`、`declined`、`unavailable` 这种结果参数给 UI 控件。签名或拒签只能来自签名审阅流程；未请求和技术失败也必须和角色拒签分开显示。

必须区分：

- `signed`：当前查理完成审阅并愿意签名。
- `declined`：当前查理完成审阅并明确拒绝。
- `unavailable`：技术上未完成，不是角色拒绝。
- `not_requested`：读者没有发起审阅，不是角色拒绝。

未来查理的签名保持空白，不允许做成可点击、可补签或可由读者代理签收。

## 4. 视觉方向

目标气质：

- 独立杂志：强排版、留白、章节感、编辑设计。
- 展览装置：沉浸、叙事转场、舞台化视觉。
- 安静、克制、文学性。
- 温暖、清新、带浅木、纸张和颜料质感。

可以做：

- 横向展厅感、章节推进、舞台幕间转场。
- 纸张纹理、浅木纹理、墨色、少量颜料痕迹。
- 更舒服的单主线交互。
- 克制的 Remotion 式状态动效。

不要做：

- 霓虹、赛博、玻璃拟态、夸张渐变。
- SaaS 仪表盘感。
- 过度卡片网格。
- 大量装饰性动效。
- 为了“高级”牺牲正文可读性。
- 任何像评分、胜负、人格判定的视觉暗示。

视觉装饰必须服务阅读和阶段推进。纸张、木头、颜料只做触觉线索，不能压过正文。

## 5. 动效规则

动效用于表达状态变化，不用于表演。

允许：

- 阶段进入时的轻微镜头推进。
- 页面翻页、展厅横移、灯光渐入等叙事过场。
- 保存、等待、降级、完成时的短反馈。
- 150 到 250ms 的按钮与局部状态反馈。
- 400 到 700ms 的阶段转场，但必须可被 `prefers-reduced-motion` 关闭或显著减弱。

禁止：

- 弹跳、橡皮筋、过度缓动。
- 动画 CSS layout 属性造成卡顿。
- 让用户等动画播完才能阅读或操作。
- 用动效替代文字状态。

推荐缓动：

- ease-out-quart
- ease-out-quint
- ease-out-expo

## 6. 可访问性和响应式底线

必须支持：

- WCAG AA。
- 全流程键盘可完成。
- 阶段切换后焦点进入新 `h1`。
- 保存、错误、降级和异步完成通过 `aria-live` 或明确文本提示。
- 触控目标不少于 44px。
- 320px 窄屏无横向滚动。
- 图片失败时仍能继续主流程。
- 不用颜色单独表达状态。
- `prefers-reduced-motion`。

表单规则：

- 输入必须有真实 label，不用 placeholder 代替 label。
- radio、checkbox、details、summary 优先使用原生控件。
- 技术说明使用渐进披露，不优先使用 modal。

## 7. 数据、隐私和本地保存

欢迎页和完成页必须诚实说明数据边界。

必须保持：

- 默认不记录研究 analytics。
- 拒绝匿名记录也能完整体验。
- 研究记录只保存允许字段，不保存完整自由输入、原话依据、完整 Prompt、模型完整输入、API 密钥、身份信息、人格标签或心理诊断。
- 体验进度和 analytics 分开保存。
- 未完成体验 24 小时后过期。
- 完成档案只读，保留到用户删除本地数据或清除站点数据。

前端不能把 `localStorage`、IndexedDB 或 React state 显示成服务器已保存，也不能在保存失败时假装已经推进。

## 8. 模型与降级展示

模型结果只是一种候选，不是可信事实。

前端必须展示：

- 当前请求模式是 Mock 还是 Live。
- 实际执行结果是否降级。
- 技术失败是否发生。
- 哪些内容来自固定内容包，哪些来自模型候选。

禁止：

- 把 Mock 写成真实 AI 完成。
- 把技术失败写成角色拒绝。
- 把 unavailable 写成 declined。
- 展示未经校验的模型原始输出。
- 执行模型输出中的链接、脚本或 tool-like 文本。

## 9. 前端实现边界

主要入口：

- `src/stage5/experience-client.tsx`：页面投影和交互控件。
- `src/stage5/contracts.ts`：前端可使用的视图和命令类型。
- `src/stage5/facade.ts`：命令入口，负责把 UI 意图转成应用命令。
- `src/stage5/projection.ts`：从 Session/FSM 投影成前端 view。
- `src/app/globals.css`：当前全局视觉层。

重构时遵守：

- UI 只消费 `Stage5PresentationView` 和 `Stage5Commands`。
- 不在展示组件里创建业务 ID。
- 不在展示组件里直接改 revision、diff、semantic fragment、signature status 或 final envelope。
- 不直接操作 Session 对象。
- 不绕过 `Stage5ExperienceFacade` 调 reducer。
- 不把 React local state 当成业务真相。
- 不把 `docs/` 当成普通说明文件夹；这里只有规则、契约、检查清单和约束文档。

推荐组件拆分：

- `ExperienceHeader`
- `GalleryAside`
- `ResearchConsentPanel`
- `PortraitCard`
- `RoundReviewPanel`
- `ManuscriptDocuments`
- `DiffReview`
- `SemanticFragmentCard`
- `SignatureReviewCard`
- `DispositionPicker`
- `FinalEnvelope`

组件拆分只能降低复杂度，不能引入新的业务判断层。

## 10. 验收清单

每次前端重构后至少验证：

```bash
pnpm typecheck
pnpm exec playwright test tests/e2e/stage5.spec.ts --reporter=line
```

如果动到 Live、签名审阅、DeepSeek、降级或 Stage 6：

```bash
pnpm exec vitest run tests/stage6/facade-live.test.ts
```

如果动到内容包、资产、生产内容或发布配置：

```bash
pnpm test:stage8:production-scan
pnpm build
```

人工检查：

- 从 `/` 开始，而不是复用旧 session 链接。
- 320px 宽度完整走主路径。
- 键盘完整走主路径。
- 图片失败时不阻塞。
- 刷新后恢复当前阶段。
- 完成页是只读封套。
- 签名页没有玩家决定签名结果的按钮。
- 语义安放没有恢复成三选一处置菜单。
